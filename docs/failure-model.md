# Failure model and injected results

The integration suite uses a disposable PostgreSQL database. Some tests kill a child process, terminate a PostgreSQL connection, or block a worker's database dialer. Tests shorten or force lease expiry to reach recovery paths quickly. These deadlines are correctness bounds, not throughput or production recovery measurements.

| Injection and test | Expected and observed behavior | Invariant checked | Recovery time in test | Duplicate or lost work | Fix made |
| --- | --- | --- | --- | --- | --- |
| Kill worker during `sleep` (`TestKilledWorkerJobIsReclaimed`) | Another worker reclaimed the expired lease and succeeded on attempt two. | Expired work is recoverable; old ownership cannot finish. | After forced expiry, second execution finished inside eight seconds. | First execution was interrupted; no external effect. | Lease reclaim and fencing were already present. |
| Kill after a simulated effect, before acknowledgment (`TestCrashAfterEffectBeforeAcknowledgement`) | The replacement worker completed the job. The marker file contains two effects. | PostgreSQL records one current attempt while external effects may repeat. | The next claim after forced expiry recovered the job. | One duplicate external effect; no lost job. | No automatic fix is possible for an arbitrary external effect. Consumers need an idempotency key or downstream fencing. |
| Kill API after enqueue commit, before response (`TestAPICrashAfterEnqueueCommit`) | The job remained durable. Retrying the same request and key returned its original ID. | Committed enqueue survives API death; one key maps to one job. | Immediate client retry after the kill. | No duplicate job or lost row. | Existing idempotency handling was verified. |
| Kill worker while delayed work waits (`TestScheduledJobSurvivesWorkerDeath`) | A replacement worker claimed the job after its due time. There is no separate scheduler process to crash. | Due work stays in PostgreSQL. | Within three seconds of the test's one-second schedule. | One execution, no lost job. | Existing worker-driven scheduling was verified. |
| Terminate a PostgreSQL backend (`TestTerminatedDatabaseConnectionRecovers`) | The affected operation could fail. An idempotent retry reconnected and the job succeeded. | A connection error must not imply that a write did or did not commit. | Immediate retry succeeded in the test. | One job after retry. | The failure report now calls out the required client retry. |
| Block new dials and close live worker connections for 450 ms (`TestTemporaryDatabaseNetworkOutageRecovers`) | Renewal failed, the worker abandoned its first execution, and a later claim succeeded. | A connection outage does not permit an unfenced completion. | Completed within five seconds after the injected outage. | Two attempts; the built-in `sleep` task has no external effect. | Existing lease recovery was verified with a real connection-path fault. |
| Stall one claim until its context deadline (`TestSlowClaimTimesOutAndWorkerContinues`) | A 100 ms claim timeout ended the stall and the next poll completed the job. | One slow database call must not hold the worker forever. | Next poll after the 100 ms deadline; job finished inside three seconds. | One claim and execution; no loss. | Added a configurable `ClaimTimeout` on the worker, defaulting to five seconds. |
| Submit one key 12 times concurrently (`TestIdempotentSubmission`) | One request created a row; the others returned the same ID. Changed input received `409`. | Unique submission identity survives concurrency. | Responses completed during the test. | One job, no duplicate. | Existing unique key and request hash were verified. |
| Expire a lease while an executor remains blocked (`TestLongExecutorCannotOverwriteNewLease`) | A second worker completed the job; the late first result could not replace it. | Only the current owner and token may finish. | Second worker finished inside three seconds of forced expiry. | Execution may overlap; stored result was not duplicated or lost. | Existing fencing was verified while both workers were live. |
| Age a heartbeat by 20 seconds (`TestWorkerRegistryAndReadAPIs`) | The worker read API reported it unhealthy. Job recovery still followed lease expiry. | Heartbeat state does not grant ownership. | Visibility changes at the ten-second health threshold. | No job transition or duplicate effect from heartbeat alone. | Existing registry behavior was verified. |
| Submit an always-failing retryable task (`TestRetryAndDeadLetterReplay`) | The job entered `dead_lettered` at its attempt budget. Replay preserved prior attempts. | Retry count is bounded; dead letters need explicit replay. | Terminal after the configured attempt; replay ran when requested. | Replay can repeat a real external effect. | Existing attempt budget and replay were verified. |
| Malformed payload (`TestDurableEnqueueAndWorker`) | The API rejected invalid input. A malformed row inserted directly into storage failed when the worker executed it. | Bad input cannot strand the worker or silently succeed. | API rejection was immediate; stored row failed on its first attempt. | No external effect. | Existing validation was verified. |
| Executor panic (`TestExecutorPanicDoesNotKillWorker`) | The attempt failed with `executor panic`; the same worker finished the next job. | One task cannot crash the worker loop. | Next poll after the failed attempt, inside three seconds. | No lost job. | Added panic recovery around the executor call. |
| SIGTERM with a 100 ms shutdown budget (`TestShutdownTimeoutLeavesLeaseForRecovery`) | The worker exited with failure while a job was running; a replacement completed the expired lease. | Forced shutdown leaves durable work recoverable. | Process exited inside two seconds; recovery finished inside three seconds after forced expiry. | A side-effecting task could run twice. | Added `WORKER_SHUTDOWN_TIMEOUT`; default remains 20 seconds. |
| Fail attempt insertion after spending a rate token (`TestClaimRollbackPreservesJobAndRateToken`) | The claim failed, but the job, attempt count, and token balance stayed unchanged. | Claim and queue controls commit atomically. | The next claim succeeded after removing the injected constraint. | No duplicate or lost work. | Existing transaction boundary was verified. |
| Request cancellation, then expire the worker lease (`TestCancelledExpiredLeaseCannotRunAgain`) | The job became `cancelled` and was never reclaimed, with one expired attempt recorded. | Cancellation survives worker death and prevents later execution. | The next worker poll after forced expiry finalized cancellation. | No duplicate execution after the request. | Fixed expired-lease cleanup to honor cancellation before reclaim or dead-lettering. |

The side-effect test uses a file marker at the storage boundary; the built-in executors do not call external systems. The outage test blocks the worker's network path to PostgreSQL; it does not stop the PostgreSQL server itself. A full server restart, backup recovery, and multi-host partition remain deployment tests.
